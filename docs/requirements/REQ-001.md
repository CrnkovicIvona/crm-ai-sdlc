# REQ-001: Bank employee access to BankCRM

- Work item (proposed): AUTH-001
- Issue: [#5](https://github.com/CrnkovicIvona/crm-ai-sdlc/issues/5)
- Status: Draft
- Author: Agent (from the human business request; not approved)

## Problem

Bank employees need to log into BankCRM before they can use the
application. Access must be limited to authenticated users. Employees
have two roles with different access. Employees must be able to log
out.

## Stated requirements

Quoted from the human business request. Nothing below is added as
product behavior.

1. Bank employees need to log into BankCRM before they can access the
   application.
2. The application has two user roles: ADMIN and VIEWER.
3. An ADMIN user has full access to the CRM.
4. A VIEWER user has read-only access.
5. Only authenticated users may access the CRM.
6. Users must be able to log out.

## Meaning of roles (as stated only)

- ADMIN: full access to the CRM.
- VIEWER: read-only access.

What “full access” and “read-only” apply to is **TBD (human)** until
other CRM capabilities exist or are specified. This requirement does
not invent CRM modules (customers, accounts, etc.).

## Out of scope (not stated in the request)

Do not treat these as approved requirements:

- How a user proves identity (password, SSO, or other)
- How users and roles are created or assigned
- Password reset, MFA, lockout, session duration
- Remember-me, multiple devices, concurrent sessions
- Any CRM business module beyond access control
- Unstated error messages, branding, or languages

## Open questions

TBD (human) — required before implementation, not guessed here:

1. How does a bank employee log in (identifier + secret, SSO, other)?
2. Who creates employee accounts and assigns ADMIN vs VIEWER?
3. Can one person have both roles, or exactly one?
4. What happens when login fails (message, retry, lockout)?
5. When is a session over besides explicit logout (timeout)?
6. After logout, must the next access require login again? (Implied by
   “only authenticated users”, but timeout/back-button is unspecified.)
7. What must VIEWER be able to read, and what must ADMIN be able to
   change, while no other CRM features exist?
8. Is the login surface the only thing an unauthenticated person may
   see?

## Implementation scope (functional, first increment)

In scope when this requirement is approved, still without choosing
libraries:

- A way for a bank employee to log in
- Denial of CRM access when not authenticated
- Distinction between ADMIN (full CRM access) and VIEWER (read-only)
- A way for an authenticated user to log out

Out of scope until a human adds it: provisioning, password policies,
SSO, MFA, CRM data features.

Technical stack (React, hosting, database, auth vendor) is **not**
part of this requirement. It belongs in an implementation plan after
Definition of Ready and human answers to the questions above.
