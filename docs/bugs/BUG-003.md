# BUG-003: Success notice `Client saved.` is easy to miss

- Issue: none (GitHub Issue not opened; recorded in git)
- Severity: Low
- Status: Fixed (PR to `test`; not Verified, not Closed)
- Feature / AC / TC: CRM-001 / BD-T012 / TC-C004, TC-C005
  (`data-testid="client-success"`)
- Production escape: no (message already appears; copy unchanged)
- RCA: [BUG-003-RCA.md](BUG-003-RCA.md) (Low cosmetic; short note)

## Symptoms

After ADMIN clicks Save and the update succeeds, the frozen string
`Client saved.` is shown (`client-success`) but uses default body
text (no success colour, no banner). It is easy to miss, so it does
not read as a validation / confirmation.

The same `client-success` node is used for `Client created.` and
`Client deleted.` on the list after navigation.

## Evidence

- PO 2026-09-14: after a successful save, the notice is present but
  not visually distinct as validation.
- CSS: errors (`client-error`) have danger colour, left border, and
  icon; `client-success` had no matching treatment.

## Workaround

Read the page for the plain `Client saved.` line, or re-open the
record. Not the intended confirmation UX.

## Expected behavior

BD-T012 copy stays exactly `Client saved.` (and created/deleted).
The notice is green, with a success banner (border + icon, not
colour-only) so it is clearly a successful validation.

## Root cause

CRM-001 UI pass styled field/form errors; success notices were left
as unstyled body copy.

## Fix

`src/index.css`: `--crm-success` / `--crm-success-bg`; style
`[data-testid='client-success']` with green text, weight, left
border, tinted background, and check icon (CSS background; DOM text
unchanged for Playwright). `role="status"` on the existing nodes.
