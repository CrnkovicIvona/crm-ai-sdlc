## Symptoms

On the same Production database and the same **Last 30 days** preset:

- VIEWER: Active 620, New 620, Churned **0**, Churn Rate N/A, Net +620
- ADMIN: Active 620, New **815**, Churned **195**, Churn Rate N/A, Net +620

A VIEWER is shown a “no churn” dashboard. An ADMIN is shown 195
churned and 195 extra new (net still +620).

## Investigation (DASH-B002 / DASH-B012)

Repo evidence (no service role, no policy edit):

- Loader: [`src/lib/dashboard.ts`](../../src/lib/dashboard.ts) —
  `client_lifecycle_stamps` (TD-D005); falls back to `clients` only
  if the view is missing on the target database.
- RLS: [`supabase/migrations/20260823210000_products_and_soft_delete.sql`](../../supabase/migrations/20260823210000_products_and_soft_delete.sql)
  - VIEWER+ADMIN: SELECT only `deleted_at is null`
  - ADMIN only: SELECT `deleted_at is not null`
- CRM list still `.is('deleted_at', null)` in
  [`src/lib/clients.ts`](../../src/lib/clients.ts) (correct for the
  register).

That matches the UI delta: VIEWER cannot see churn events or
created-then-deleted rows without the stamps view.
