# BUG-004: VIEWER dashboard omits churn / new that ADMIN sees

- Issue: none (GitHub Issue not opened; recorded in git)
- Severity: High
- Status: New
- Feature / AC / TC: DASH-001 / FR-D003, FR-D004 / actors table
  (VIEWER views all dashboard data); related CRM-001 SELECT / soft-delete
- Production escape: yes (observed on Production
  `https://crm-ai-sdlc.vercel.app/` 2026-09-19)
- RCA: required (High + production). Not written this session.

## Symptoms

On the same Production database and the same **Last 30 days** preset:

- VIEWER: Active 620, New 620, Churned **0**, Churn Rate N/A, Net +620
- ADMIN: Active 620, New **815**, Churned **195**, Churn Rate N/A, Net +620

A VIEWER is shown a “no churn” dashboard. An ADMIN is shown 195
churned and 195 extra new (net still +620).

## Evidence

Exploratory session [EXP-2026-09-19-2](../test-reports/EXP-2026-09-19-2.md).
Live UI only (login-page VIEWER then ADMIN). No service role. No
PostgREST trace.

DASH-001: VIEWER shall access and view all dashboard data; New counts
`created_at` in range even if later deleted; Churned counts
`deleted_at` in range.

## Workaround

Use ADMIN to read churn / new-including-deleted. VIEWER dashboard is
not a reliable churn view until this is triaged.

## Expected behavior

VIEWER and ADMIN see the **same** dashboard metrics for the same
period, or the product documents a deliberate VIEWER slice and the
UI explains it. Current UI does not explain a role split.
