# BUG-002: Dashboard and Clients nav labels run together

- Issue: none (GitHub Issue not opened; recorded in git)
- Severity: Low
- Status: Fixed (PR to `test`; not Verified, not Closed)
- Feature / AC / TC: DASH-001 / AC-D001 /
  `tests/e2e/dashboard.spec.ts` (`nav-dashboard`, `nav-clients`)
- Production escape: no (layout on Production with DASH-001;
  increment **`RELEASED`** after REL-007 smoke)
- RCA: not required (Low, not a production escape)

## Symptoms

In the authenticated shell top bar, **Dashboard** and **Clients**
rendered as a single visual string (`DashboardClients`) with no gap
and no button chrome. They were still two `Link`s, but they did not
look like separate clickable controls.

## Evidence

- PO screenshot 2026-09-14: BankCRM header shows blue
  `DashboardClients` as one run-on label above the Clients heading.
- Cause in CSS: `.crm-topbar nav a { margin-right: 0 }` with no
  `gap`, padding, or border between adjacent text links.
- Repeatability: always, on the DASH-001 shell after `#41` landed on
  `test`. Not flaky.

## Workaround

The two destinations still had distinct `data-testid` targets
(`nav-dashboard`, `nav-clients`). Users could guess the click
regions. Not acceptable as the intended UI.

## Expected behavior

Dashboard and Clients are separate, clickable buttons with visible
space between them, consistent with other shell controls (for
example Log out). The active route is visually distinct.

## Root cause

DASH-001 added a second shell `Link` next to Clients. Existing
`.crm-topbar nav a` removed the only spacing (`margin-right: 0`) and
kept the items as undecorated text, so adjacent labels concatenated.

## Fix

`src/pages/AppShell.tsx` + `src/index.css`: `NavLink` items in
`.crm-nav` with flex `gap`, button padding/border, and `.active`
accent fill. Testids unchanged.

PR: [#42](https://github.com/CrnkovicIvona/crm-ai-sdlc/pull/42)
(`cursor/dash-001-dashboard-73b9` → `test`). Commit `49458f5`.
